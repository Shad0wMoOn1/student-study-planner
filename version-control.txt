НАЗНАЧЕНИЕ СИСТЕМЫ УПРАВЛЕНИЯ ВЕРСИЯМИ

Система управления версиями сохраняет историю изменений файлов проекта.
Она помогает выяснить, кем и зачем сделано изменение, сравнить состояния
и при необходимости восстановить подходящую версию.

Git — распределенная система управления версиями. Полный локальный
репозиторий обычно содержит историю проекта и позволяет создавать коммиты
без подключения к серверу. GitHub — веб-сервис для размещения Git-репозиториев
и совместной работы; Git и GitHub не являются одним и тем же продуктом.

Репозиторий объединяет файлы, историю и ссылки на версии.
Коммит фиксирует состояние проекта, связан с родительскими коммитами,
содержит автора и сообщение. Понятное сообщение объясняет смысл изменения.
Ветвь — перемещаемая ссылка на коммит, задающая отдельную линию разработки.
Создание ветви само по себе не создает новый коммит и не дублирует все файлы.

Pull request в GitHub — предложение перенести изменения из одной ветви
в другую с возможностью обсуждения и проверки. Base — целевая ветвь,
compare — ветвь с предлагаемыми изменениями.
Слияние (merge) объединяет изменения и историю линий разработки.
Если изменения пересекаются и Git не может объединить их автоматически,
возникает конфликт: его нужно разрешить и проверить результат.

Fork — отдельный репозиторий в аккаунте пользователя, связанный с исходным
проектом на GitHub. Fork отличается от ветви внутри того же репозитория
и от скачанного ZIP-архива. Скачивание ZIP не создает fork.

В проекте student-study-planner дополнительные материалы изолированы
в feature-materials, а этот документ добавляется в feature-guide.
Для включения документа в основную версию создается pull request
из feature-guide в main. После merge ветвь feature-guide сохраняется,
а feature-materials остается самостоятельным вариантом проекта.
